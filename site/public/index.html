Push to GitHub. It's live on the Mac in your closet.

Berth is a dead simple PaaS for Mac minis. A few seconds after you push, your app is running in its own little VM at https://myapp.yourdomain.com. Postgres is one command away, and there's no monthly bill per app.

Three commands, then just git push

No ports opened on your router, no certificates, no YAML, no Docker Desktop, and no sudo once it's set up.

  1. Install it on the Mac. Homebrew brings Apple's container runtime, Caddy and cloudflared along with it.
  2. Run berth init once. It connects your Cloudflare domain and GitHub in the browser. About three minutes.
  3. Create an app. Berth adds a webhook to the repo, so every push to main after that deploys itself.
brew tap dps/berth https://github.com/dps/berth
brew trust dps/berth
brew install berth

berth init --domain example.com       # once
berth create myapp --repo you/myapp  # once per app
git push                             # every deploy after that

The boring parts, done once

Each piece of Berth exists because something was annoying without it.

Deploys without downtime

The new release has to answer before it gets traffic, and the old one drains. Every deploy is a numbered release you can roll back to.

Postgres, Redis and SQLite

One command each, linked into the app's config. Dumped every night, and again before every migration runs.

A dev version for your agent

Every app gets myapp-dev, with its own copy of the data. A coding agent can push uncommitted work there and check it really works.

Pull request previews

Each pull request gets its own address, posted as a comment on the PR, and goes away when it closes.

Sign in with Google

Put any app behind Google sign-in: for everyone, for a list of people, or only on the pages that need it. Your app just reads a header.

Workers and cron

Procfile workers run beside your web process and come back if they crash. Scheduled jobs come from app.json.

AI for every app

One gateway for small models running on the Mac and cloud models with your keys, with a budget and usage for each app.

An admin page

Every app's health, requests, latency and errors, plus the Mac's load, at admin.yourdomain.com, for the owners you name.

Backups that leave the house

Encrypted on the Mac, then uploaded to Cloudflare R2 or any S3 bucket. A new Mac comes back from one recovery code.

How it works

A Mac mini is a great home for small apps. It's quiet, it sips power, and an M4 with 16 GB runs twenty-odd apps and a couple of databases comfortably.

git

You push

GitHub tells Berth over a webhook. Public repos work without one; Berth polls them.

build

The Mac builds it

From your Dockerfile, or one Berth writes for Node, Bun, Python, Go, Rust or a static site.

VM

Each app gets a VM

Apple's container runs every app in its own lightweight Linux VM, with its own memory limit.

https

Cloudflare brings visitors in

A tunnel connects out from the Mac, so nothing at home is open to the internet. HTTPS just works.

What it isn't

It's one Mac. There's no failover, and if the power goes out while you're on holiday, your apps are down until it comes back.

That's the right trade for side projects, internal tools, family apps and prototypes. It's the wrong one for anything where an hour of downtime costs real money.
